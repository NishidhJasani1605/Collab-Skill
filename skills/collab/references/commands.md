# COLLAB Internal Command Reference

COLLAB uses a local, JSON-based internal CLI (`scripts/collab.py`) executed by the agent. Users invoke `/collab`, and the skill executes the appropriate helper commands autonomously.

Only `start` may initialize `.collab/`. Before activation, other commands return
`NOT_INITIALIZED` without creating project files. Installation verification uses
`collab.py --version`, never `start`. Existing state may be recovered under the
lock even during `read` or `status`.

Mutating commands other than `start` require:
- `agent_id`: The ID returned during `start`.
- `token`: The private authentication token returned during `start` (can also be supplied via `COLLAB_TOKEN` in the environment).
- `task_id`: The ID of the task being operated on.

Mutations other than `start` and `check` accept an optional `key` string (up to 256 characters) for idempotent retry protection. Resume `start` using the session ID and token; each `check` invocation executes the declared command again.

Pass input via `--input <file>` (or `-` for stdin) using a UTF-8 JSON object to avoid shell quoting and process argument exposure.

## 1. Lifecycle and Discovery

### `start`
Join an existing open task or initialize a new task in the project workspace.
- **Input parameters:**
  - `name`: Display name of the agent (e.g., `"Codex"`, `"Antigravity"`). Required when registering a new session.
  - `session_id`: Unique session string generated by the agent.
  - `objective`: Primary user goal (required when creating a new task; used to match or create tasks).
  - `task_id`: (Optional) Existing open task ID to join directly.
  - `new_task`: (Optional) Boolean (default: `false`). When `true`, explicitly creates a new task if no open task shares the same objective.
  - `platform`: (Optional) Host environment (e.g., `"vscode"`, `"cli"`, `"antigravity"`, default: `"unknown"`).
  - `model`: (Optional) Model identifier if known, otherwise `"unknown"`. Never fabricate model names.
  - `criteria` / `acceptance_criteria`: (Optional) List of strings defining completion gates.
  - `checks`: (Optional) List of command specifications:
    `[{"name": "test-suite", "argv": ["python", "-m", "pytest"], "timeout": 120}]`
  - `artifacts` / `required_artifacts`: (Optional) List of relative file paths that must exist for finalization.
  - `independent_reviews`: (Optional) Minimum number of passing independent reviews (default: 1).
  - `token`: (Optional) Required only when resuming an existing registered `session_id`.
- **Returns:**
  - `agent`: Agent identity object (`id`, `name`, `platform`, `model`, `status`, `stale`).
  - `token`: Private bearer token (must be retained in session memory).
  - `task`: Task object (`id`, `objective`, `status`, `participants`, `required_participants`, `assignments`, `criteria`, `required_artifacts`).
  - `agents`: List of all registered agent public profiles in the workspace.
  - `cursor`: 1-indexed event sequence number (`seq`) for incremental reading.
  - `events`: List of up to 30 recent group chat events for the joined task.
  - `observer`: Boolean (`true` if joining during an active `REVIEW` round).

### `read`
Read new group chat events incrementally without re-reading the entire transcript.
- **Input parameters:**
  - `after` / `cursor`: Integer sequence number (`seq`) from the previous read (default: 0).
  - `limit`: Maximum number of events to return (default: 100, max: 1000).
  - `task_id`: (Optional) Filter events by specific task ID.
- **Returns:**
  - `events`: Array of new event objects with `seq > after`.
  - `cursor`: Updated sequence number (`seq`) scanned for subsequent reads.
  - `latest`: Highest sequence number currently committed in `GROUP_CHAT.jsonl`.

### `status`
Inspect the current team and task state without modifying it.
- **Input parameters:**
  - `task_id`: (Optional) Specific task ID to inspect. When omitted, returns all tasks in `tasks`.
- **Returns:**
  - `task`: Detailed task state, assignments, issues, help requests, active proposal, check runs (when `task_id` is supplied).
  - `blockers`: List of remaining completion blockers for the task (when `task_id` is supplied).
  - `tasks`: List of all task objects (when `task_id` is omitted).
  - `agents`: List of all registered agents and their current statuses.
  - `reservations`: List of file reservation records.
  - `cursor`: Latest committed sequence number (`seq`).

### `checkpoint`
Save session checkpoint summary for persistence across restarts.
- **Input parameters:**
  - `content` / `summary` / `description`: Short progress and state description.
  - `active_file`: (Optional) Relative path of the project file currently being worked on.
- **Returns:**
  - `checkpoint`: Checkpoint record with `agent_id`, `content`, `active_file` (if supplied), `timestamp`, and `cursor` sequence position.

### `agent-status`
Update the agent's published lifecycle status.
- **Input parameters:**
  - `status`: Case-insensitive status string; one of `JOINED`, `PLANNING`, `WORKING`, `BLOCKED`, `HELPING`, `REVIEWING`, `OFFLINE` (`WORK_COMPLETE`, `APPROVED`, and `TEAM_COMPLETE` require their dedicated commands).
- **Returns:**
  - `agent`: Updated public agent object.

## 2. Group Conversation

### `send`
Post a structured event to `GROUP_CHAT.jsonl` and update `GROUP_CHAT.md`.
- **Event types (`CHAT_TYPES`):**
  - `PLAN`: Propose a roadmap or strategy (transitions a `JOINED` agent to `PLANNING`).
  - `STATUS`: Report milestones or active steps (default when `type` is omitted).
  - `QUESTION`: Ask teammates for information.
  - `REPLY`: Answer a teammate's question.
  - `FINDING`: Share an observation in chat.
  - `SUGGESTION`: Suggest an alternative or improvement.
  - `HELP_REQUEST` / `HELP_RESPONSE`: Chat-level help discussion.
  - `FILE_CHANGE`: Note modifications made to project files.
  - `ISSUE` / `REVIEW` / `REJECTION` / `DECISION`: Structured coordination messages.
  - `DISAGREEMENT`: Challenge a finding or propose a correction (automatically creates a blocking issue in task state and invalidates active review).
- **Input parameters:**
  - `type`: (Optional) Event type string (default: `"STATUS"`).
  - `content` / `message` / `summary`: Markdown text message.
  - `recipient`: (Optional) Target registered `agent_id`.
  - `reply_to`: (Optional) Existing message `id` being replied to.
  - `files`: (Optional) List of referenced relative project file paths.
  - `evidence`: (Optional) List of evidence objects or strings.
  - `key`: (Optional) Idempotency key to prevent duplicate submissions.

## 3. Task and Assignment Coordination

### `assignment-add`
Declare a discrete unit of work within the task.
- **Input parameters:**
  - `title` / `name`: Short title of the assignment.
  - `description` / `content` / `summary` / `detail`: (Optional) Scope of work and details.
  - `files`: (Optional) Target relative project file paths.
  - `depends_on` / `dependencies`: (Optional) List of prerequisite assignment IDs in this task that must be completed first.
  - `required`: (Optional) Boolean indicating whether completion is required before team completion (default: `true`).
- **Returns:**
  - `assignment`: The created assignment record.

### `claim`
Take ownership of an open assignment once all its `depends_on` assignments are `WORK_COMPLETE`.
- **Input parameters:**
  - `assignment_id` / `id`: ID of the assignment to claim.
- **Returns:**
  - `assignment`: Updated assignment record with `owner` set to calling agent and `status` set to `"WORKING"`.

### `progress`
Update completion percentage of an active assignment.
- **Input parameters:**
  - `assignment_id` / `id`: Owned assignment ID.
  - `percent`: Integer between 0 and 99.
  - `content` / `status_message` / `message` / `summary`: (Optional) Progress description (default: `"Progress updated"`).
- **Returns:**
  - `assignment`: Updated assignment record.

### `work-complete`
Mark an individual assignment complete. **Never completes the team task.** Also records the agent's `participant_results` entry.
- **Input parameters:**
  - `assignment_id` / `id`: Owned assignment ID.
  - `result` / `content` / `summary`: Summary of the completed output.
  - `evidence`: (Optional) List of proofs (file paths, test commands, outputs).
- **Returns:**
  - `assignment`: Completed assignment record (`status: "WORK_COMPLETE"`, `percent: 100`).

### `participant-result`
Submit an individual contribution or analysis when no formal assignment was claimed.
- **Input parameters:**
  - `content` / `result` / `summary`: Summary of findings or contribution.
  - `evidence`: (Optional) List of supporting facts, checks, or files.
- **Returns:**
  - `participant_result`: Recorded participant contribution (`content`, `evidence`, `timestamp`).

## 4. Assistance and Issue Tracking

### `help-request`
Broadcast a request for assistance when blocked. Creates a blocking condition on finalization and sets the agent status to `BLOCKED`.
- **Input parameters:**
  - `content` / `description` / `detail` / `summary`: Blocker description (or combined `title` and `description`/`detail`).
  - `title`: (Optional) Summary headline.
  - `description`: (Optional) Detailed explanation of what is needed.
  - `assignment_id`: (Optional) Related assignment ID in the task.
- **Returns:**
  - `help`: Open help request record (`status: "OPEN"`).

### `help-respond`
Offer an answer or solution to an open help request. Sets the responder's status to `HELPING` and the help request status to `ASSISTING`.
- **Input parameters:**
  - `help_id` / `id`: ID of the open help request.
  - `content` / `solution` / `resolution` / `response` / `summary`: Explanation and suggested fix.
  - `evidence`: (Optional) Supporting evidence items.
- **Returns:**
  - `help`: Updated help record with response appended.

### `help-resolve`
Resolve the help request. Only the requesting agent (or operator-assigned `resolution_owner`) may resolve their request after verifying the fix.
- **Input parameters:**
  - `help_id` / `id`: ID of the help request.
  - `content` / `solution` / `resolution` / `response` / `summary`: Explanation of what resolved the issue.
- **Returns:**
  - `help`: Resolved help record (`status: "RESOLVED"`).

### `issue`
Raise an issue, bug, or risk found during investigation or implementation.
- **Input parameters:**
  - `content` / `description` / `detail` / `summary`: Details and reproduction steps (or combined `title` and `description`/`detail`).
  - `title`: (Optional) Headline of the issue.
  - `description`: (Optional) Extended reproduction steps.
  - `blocking`: (Optional) Boolean (default: `true`). Blocking issues prevent team finalization.
  - `evidence`: (Optional) Supporting evidence.
- **Returns:**
  - `issue`: Created issue record (`status: "OPEN"`).

### `resolve`
Mark an open issue resolved. The original author (or operator-assigned `resolution_owner`) must confirm.
- **Input parameters:**
  - `issue_id` / `id`: ID of the open issue.
  - `content` / `resolution` / `solution` / `summary`: Explanation of the resolution.
  - `evidence`: List of reproducible evidence (mandatory and non-empty for blocking issues).
- **Returns:**
  - `issue`: Resolved issue record (`status: "RESOLVED"`).

### `finding`
Publish an important factual discovery, defect, or metric.
- **Input parameters:**
  - `content` / `detail` / `description` / `summary` / `result`: Finding analysis (or combined `title` and `detail`/`description`).
  - `title`: (Optional) Finding headline.
  - `detail`: (Optional) Extended analysis.
  - `files`: (Optional) Affected relative project file paths.
  - `evidence`: (Optional) Proof or verification steps.
- **Returns:**
  - `finding`: Finding record saved in task state and `.collab/findings/<finding_id>.json`.

## 5. File Coordination and Editing

### `reserve`
Acquire a temporary cooperative lease on one or more project files.
- **Input parameters:**
  - `files` / `paths` (or single string `path` / `file`): Relative project file path(s) to reserve.
  - `ttl_seconds` / `ttl`: (Optional) Lease duration in seconds (default: 900, range: 1 to 3600).
- **Returns:**
  - `reservation`: Reservation record with `id`, `files`, `base_hashes`, and `expires_at`.

### `file-write`
Perform an atomic, hash-verified write to a reserved file.
- **Input parameters:**
  - `reservation_id` / `id`: Active reservation ID owned by the calling agent.
  - `path` / `file`: Target reserved relative file path.
  - `expected_hash`: SHA-256 hash matching both the reservation's `base_hashes[path]` and current on-disk file (`"missing"` for a new file).
  - `content`: UTF-8 file content (must be at most 4 MiB).
- **Returns:**
  - `change`: File change record (`before`, `after`, `files`, `method`).
  - `reservation`: Updated reservation record with `base_hashes[path]` updated to `after`.

### `file-record`
Record file modifications when edits were made using native host tools.
- **Input parameters:**
  - `reservation_id` / `id`: Active reservation ID owned by the calling agent.
  - `path` / `file`: Modified reserved relative file path.
  - `expected_hash`: (Optional) If supplied, verifies the current on-disk file hash matches `expected_hash` before recording.
- **Returns:**
  - `change`: File change record (`before`, `after`, `files`, `method`).
  - `reservation`: Updated reservation record with `base_hashes[path]` updated to `after`.

### `release`
Explicitly release a file reservation so teammates can reserve it and finalization is unblocked.
- **Input parameters:**
  - `reservation_id` / `id`: Active reservation ID owned by the calling agent.
- **Returns:**
  - `reservation`: Released reservation record (`released: true`).

## 6. Review and Completion

### `propose`
Submit a candidate solution revision for team review. Transitions task status to `REVIEW` and freezes required review membership for that round.
- **Input parameters:**
  - `content` / `summary` / `result` / `description`: Description of proposed changes and solution summary.
  - `files`: (Optional) Additional modified/created project files to fingerprint.
  - `artifacts` / `required_artifacts`: (Optional) Artifact files to bind to the proposal and require on disk for finalization.
  - `criteria` / `acceptance_criteria`: (Optional) Additional acceptance criteria to bind to the task.
  - `limitations`: (Optional) List of known constraints or caveats.
- **Returns:**
  - `revision`: Monotonically increasing revision number.
  - `decision`: Decision object containing `digest`, `file_hashes`, `members`, `limitations`, and `content`.

### `check`
Execute a pre-declared automated test or verification check against the current active proposal revision.
- **Input parameters:**
  - `name` / `check`: Identifier of the check declared during `start`.
- **Returns:**
  - `check`: Check run record including `returncode`, `revision`, `digest`, `log_path`, and `log_hash`.

### `review`
Submit an independent evaluation of the active proposal revision.
- **Input parameters:**
  - `revision`: (Optional) Proposal revision number being reviewed (defaults to active revision; must match active revision).
  - `verdict`: `"APPROVE"` or `"REJECT"` (case-insensitive).
  - `content` / `critique` / `review` / `summary` / `comment`: (Optional) Review critique and justification (default: `"Independent review completed"`).
  - `evidence`: Non-empty list of reproducible evidence items.
- **Returns:**
  - `review`: Review record with `verdict`, `revision`, `digest`, and `evidence`.

### `approve`
Sign off on the active proposal revision. Required from all frozen team members (`decision.members`).
- **Input parameters:**
  - `revision`: (Optional) Proposal revision number (defaults to active revision; must match active revision).
  - `content` / `approval` / `summary` / `comment`: (Optional) Statement of approval (default: `"Approved active revision"`).
- **Returns:**
  - `approval`: Approval record bound to the exact revision and digest.

### `finalize`
Perform the guarded, atomic team completion operation.
- **Input parameters:**
  - `revision`: (Optional) Exact proposal revision number to finalize (defaults to active revision).
- **Prerequisites verified automatically:**
  1. At least one required assignment exists and all required assignments are completed (`WORK_COMPLETE`).
  2. All frozen review-round members (`decision.members`) submitted individual results (`work-complete` or `participant-result`).
  3. No open blocking issues or unresolved help requests.
  4. Required number of passing (`APPROVE`) independent reviews (by non-authors) with non-empty evidence, and no unresolved `REJECT` reviews on the active revision.
  5. All frozen team members have approved the active proposal revision and exact digest.
  6. All pre-declared checks passed (`returncode == 0`) on the exact proposal revision and digest with intact, untampered evidence logs on disk.
  7. No tracked project files modified since the proposal revision was fingerprinted.
  8. All required artifacts (declared in `start` or bound in `propose`) exist on disk.
  9. All file reservations for the task have been released.
- **On success:**
  - Generates `.collab/FINAL_REPORT.md` and `.collab/decisions/<task_id>-final.md`.
  - Transitions task and member statuses to `TEAM_COMPLETE`.
  - Emits the final `TEAM_COMPLETE` event to `GROUP_CHAT.jsonl` and `GROUP_CHAT.md`.

## 7. Emergency Human Operator Tool

If an agent process crashes or disconnects permanently, leaving an unfinished task blocked:

```bash
python path/to/skills/collab/scripts/collab_operator.py \
  --root . \
  --task <task_id> \
  --exclude <abandoned_agent_id> \
  --replacement <optional_substitute_agent_id> \
  --reason "Agent crashed and session is unrecoverable"
```

- Requires an interactive terminal (`isatty`).
- Presents a random security challenge phrase to prevent automated agent invocation.
- Re-opens review rounds and invalidates prior approvals to ensure unvetted changes cannot be finalized without review.
