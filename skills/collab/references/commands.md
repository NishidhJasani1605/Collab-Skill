# COLLAB Internal Command Reference

COLLAB uses a local, JSON-based internal CLI (`scripts/collab.py`) executed by the agent. Users invoke `/collab`, and the skill executes the appropriate helper commands autonomously.

All mutating commands require:
- `agent_id`: The ID returned during `start`.
- `token`: The private authentication token returned during `start`.
- `task_id`: The ID of the task being operated on.

Pass input via `--input <file>` (or `-` for stdin) using a UTF-8 JSON object to avoid shell quoting and process argument exposure.

---

## 1. Lifecycle and Discovery

### `start`
Join an existing open task or initialize a new task in the project workspace.
- **Input parameters:**
  - `name`: Display name of the agent (e.g., `"Codex"`, `"Antigravity"`).
  - `session_id`: Unique session string generated by the agent.
  - `objective`: Primary user goal (used to match or create tasks).
  - `platform`: (Optional) Host environment (e.g., `"vscode"`, `"cli"`, `"antigravity"`, default: `"unknown"`).
  - `model`: (Optional) Model identifier if known, otherwise `"unknown"`. Never fabricate model names.
  - `criteria` / `acceptance_criteria`: (Optional) List of strings defining completion gates.
  - `checks`: (Optional) List of command specifications:
    `[{"name": "test-suite", "argv": ["python", "-m", "pytest"], "timeout": 120}]`
  - `artifacts` / `required_artifacts`: (Optional) List of relative file paths that must exist for finalization.
  - `independent_reviews`: (Optional) Minimum number of passing independent reviews (default: 1).
  - `token`: (Optional) Required only when resuming an existing registered session.
- **Returns:**
  - `agent`: Agent identity object (`id`, `name`, `platform`, `model`, `status`).
  - `token`: Private bearer token (must be retained in session memory).
  - `task`: Task object (`id`, `objective`, `status`, `participants`, `assignments`).
  - `cursor`: Byte offset for incremental reading.
  - `events`: List of initial/recent group chat events.
  - `observer`: True if joining during an active review round.

### `read`
Read new group chat events incrementally without re-reading the entire transcript.
- **Input parameters:**
  - `after`: Integer byte cursor from the previous read (default: 0).
  - `limit`: Maximum number of events to return (default: 100, max: 1000).
  - `task_id`: (Optional) Filter events by specific task.
- **Returns:**
  - `events`: Array of new event objects.
  - `cursor`: Updated byte offset for subsequent reads.
  - `latest`: Highest sequence number available.

### `status`
Inspect the current team and task state without modifying it.
- **Input parameters:**
  - `task_id`: (Optional) Task ID to inspect.
- **Returns:**
  - `task`: Detailed task state, assignments, issues, help requests, active proposal, check runs, and blockers.
  - `agents`: List of all registered agents and their current statuses.
  - `reservations`: Active file reservations.

### `checkpoint`
Save session checkpoint summary for persistence across restarts.
- **Input parameters:**
  - `content` / `summary`: Short progress and state description.
  - `active_file`: (Optional) Relative path of the file currently being worked on.
- **Returns:**
  - `checkpoint`: Checkpoint record with timestamp and cursor position.

### `agent-status`
Update the agent's published lifecycle status.
- **Input parameters:**
  - `status`: One of `PLANNING`, `WORKING`, `BLOCKED`, `HELPING`, `REVIEWING`, `OFFLINE`.
- **Returns:**
  - `agent`: Updated agent object.

## 2. Group Conversation

### `send`
Post a structured event to `GROUP_CHAT.jsonl` and update `GROUP_CHAT.md`.
- **Event types:**
  - `PLAN`: Propose a roadmap or strategy.
  - `STATUS`: Report milestones or active steps.
  - `QUESTION`: Ask teammates for information.
  - `REPLY`: Answer a teammate's question.
  - `SUGGESTION`: Suggest an alternative or improvement.
  - `DISAGREEMENT`: Challenge a finding or propose a correction (creates a blocking issue).
  - `FILE_CHANGE`: Note modifications made to project files.
- **Input parameters:**
  - `type`: Event type string.
  - `content`: Markdown text message.
  - `recipient`: (Optional) Target agent ID.
  - `reply_to`: (Optional) Parent message ID.
  - `files`: (Optional) List of referenced relative file paths.
  - `evidence`: (Optional) List of evidence objects.
  - `key`: (Optional) Idempotency key to prevent duplicate submissions.

## 3. Task and Assignment Coordination

### `assignment-add`
Declare a discrete unit of work within the task.
- **Input parameters:**
  - `title`: Short title of the assignment.
  - `description` / `content`: (Optional) Scope of work and details.
  - `files`: (Optional) Target file paths.
  - `depends_on`: (Optional) List of prerequisite assignment IDs that must be completed first.
  - `required`: (Optional) Boolean indicating whether completion is required before team completion (default: true).
- **Returns:**
  - `assignment`: The created assignment record.

### `claim`
Take ownership of an open assignment.
- **Input parameters:**
  - `assignment_id`: ID of the assignment to claim.
- **Returns:**
  - `assignment`: Updated assignment record with `owner` set to calling agent.

### `progress`
Update completion percentage of an active assignment.
- **Input parameters:**
  - `assignment_id`: Owned assignment ID.
  - `percent`: Integer between 0 and 99.
  - `content` / `status_message`: (Optional) Progress description (default: `"Progress updated"`).
- **Returns:**
  - `assignment`: Updated assignment record.

### `work-complete`
Mark an individual assignment complete. **Never completes the team task.**
- **Input parameters:**
  - `assignment_id`: Owned assignment ID.
  - `result` / `content`: Summary of the completed output.
  - `evidence`: (Optional) List of proofs (file paths, test commands, outputs).
- **Returns:**
  - `assignment`: Completed assignment record.

### `participant-result`
Submit an individual contribution or analysis when no formal assignment was claimed.
- **Input parameters:**
  - `content` / `result`: Summary of findings or contribution.
  - `evidence`: (Optional) List of supporting facts, checks, or files.

## 4. Assistance and Issue Tracking

### `help-request`
Broadcast a request for assistance when blocked. Creates a blocking condition on finalization.
- **Input parameters:**
  - `content`: Blocker description (or combined `title` and `description`).
  - `title`: (Optional) Summary headline.
  - `description`: (Optional) Detailed explanation of what is needed.
  - `assignment_id`: (Optional) Related assignment ID.
- **Returns:**
  - `help`: Open help request record.

### `help-respond`
Offer an answer or solution to an open help request.
- **Input parameters:**
  - `help_id`: ID of the help request.
  - `content` / `solution`: Explanation and suggested fix.
  - `evidence`: (Optional) Supporting evidence items.
- **Returns:**
  - `help`: Updated help record with response added.

### `help-resolve`
Resolve the help request. Only the requesting agent may resolve their own request after verifying the fix.
- **Input parameters:**
  - `help_id`: ID of the help request.
  - `content` / `solution` / `resolution`: Explanation of what resolved the issue.
- **Returns:**
  - `help`: Resolved help record.

### `issue`
Raise an issue, bug, or risk found during investigation or implementation.
- **Input parameters:**
  - `content`: Details and reproduction steps (or combined `title` and `description`).
  - `title`: (Optional) Headline of the issue.
  - `description`: (Optional) Extended reproduction steps.
  - `blocking`: (Optional) Boolean (default: true). Blocking issues prevent team finalization.
  - `evidence`: (Optional) Supporting evidence.
- **Returns:**
  - `issue`: Created issue record.

### `resolve`
Mark an issue resolved. The original author (or appointed resolution owner) must confirm.
- **Input parameters:**
  - `issue_id`: ID of the issue.
  - `content` / `resolution`: Explanation of the resolution.
  - `evidence`: List of reproducible evidence (mandatory for blocking issues).
- **Returns:**
  - `issue`: Resolved issue record.

### `finding`
Publish an important factual discovery, defect, or metric.
- **Input parameters:**
  - `content`: Finding analysis (or combined `title` and `detail`).
  - `title`: (Optional) Finding headline.
  - `detail`: (Optional) Extended analysis.
  - `files`: (Optional) Affected relative file paths.
  - `evidence`: (Optional) Proof or verification steps.
- **Returns:**
  - `finding`: Finding record saved in task and `.collab/findings/`.

## 5. File Coordination and Editing

### `reserve`
Acquire a temporary cooperative lease on one or more project files.
- **Input parameters:**
  - `files`: List of relative file paths.
  - `ttl_seconds`: (Optional) Lease duration in seconds (default: 900, range: 1 to 3600).
- **Returns:**
  - `reservation`: Reservation record with `base_hashes` for safe writes.

### `file-write`
Perform an atomic, hash-verified write to a reserved file.
- **Input parameters:**
  - `reservation_id`: Active reservation ID.
  - `path`: Target file path.
  - `expected_hash`: SHA-256 hash matching the reserved baseline.
  - `content`: UTF-8 file content (must be under 4 MiB).

### `file-record`
Record file modifications when edits were made using native host tools.
- **Input parameters:**
  - `reservation_id`: Active reservation ID.
  - `path`: Modified file path.
  - `expected_hash`: (Optional) Hash check prior to recording.

### `release`
Explicitly release a file reservation so teammates can reserve it.
- **Input parameters:**
  - `reservation_id`: Active reservation ID.

## 6. Review and Completion

### `propose`
Submit a candidate solution revision for team review.
- **Input parameters:**
  - `content` / `summary`: Description of proposed changes and solution summary.
  - `files`: (Optional) Additional modified/created project files.
  - `artifacts` / `required_artifacts`: (Optional) Artifact files to bind to the proposal.
  - `limitations`: (Optional) List of known constraints or caveats.
- **Returns:**
  - `revision`: Monotonically increasing revision number.
  - `decision`: Decision object containing `digest`, `file_hashes`, `members`, and `content`.

### `check`
Execute a pre-declared automated test or verification check.
- **Input parameters:**
  - `name`: Identifier of the check declared during `start`.
- **Returns:**
  - `check`: Check run record including `returncode`, `log_path`, and `log_hash`.

### `review`
Submit an independent evaluation of the active proposal revision.
- **Input parameters:**
  - `revision`: Exact proposal revision number being reviewed.
  - `verdict`: `"APPROVE"` or `"REJECT"`.
  - `content`: Review critique and justification.
  - `evidence`: Non-empty list of reproducible evidence items.
- **Returns:**
  - `review`: Review record with `verdict`, `digest`, and `evidence`.

### `approve`
Sign off on the active proposal revision. Required from all frozen team members.
- **Input parameters:**
  - `revision`: Exact proposal revision number.
  - `content`: (Optional) Statement of approval (default: `"Approved active revision"`).
- **Returns:**
  - `approval`: Approval record bound to the exact revision and digest.

### `finalize`
Perform the guarded, atomic team completion operation.
- **Input parameters:**
  - `revision`: (Optional) Exact proposal revision number to finalize (defaults to active revision).
- **Prerequisites verified automatically:**
  1. All required assignments completed (`WORK_COMPLETE`).
  2. All required members submitted individual results.
  3. No open blocking issues or unresolved help requests.
  4. Required number of passing independent reviews with evidence.
  5. All frozen team members have approved the active proposal revision.
  6. All pre-declared checks passed on the exact proposal revision with intact logs.
  7. No files modified since proposal revision was fingerprinted.
  8. All required artifacts exist on disk.
  9. All file reservations released.
- **On success:**
  - Generates `.collab/FINAL_REPORT.md` and `.collab/decisions/<task_id>-final.md`.
  - Transitions task and member statuses to `TEAM_COMPLETE`.
  - Emits the final `TEAM_COMPLETE` event to `GROUP_CHAT.jsonl` and `GROUP_CHAT.md`.

## 7. Emergency Human Operator Tool

If an agent process crashes or disconnects permanently, leaving an unfinished task blocked:

```bash
python path/to/skills/collab/scripts/collab_operator.py \
  --root . \
  --task <task_id> \
  --exclude <abandoned_agent_id> \
  --replacement <optional_substitute_agent_id> \
  --reason "Agent crashed and session is unrecoverable"
```

- Requires an interactive terminal (`isatty`).
- Presents a random security challenge phrase to prevent automated agent invocation.
- Re-opens review rounds to ensure unvetted code cannot be finalized without review.
